# Editor Teardown & Step-by-Step Rebuild

## The problem (confirmed by code inventory)

The editor is a museum of half-wired features: 8 toolbar tools where "Compose" does nothing, "Duplicate"/"Images"/"Fullscreen" are fake tools, a "More" button that's a no-op, a Reference-mode dropdown never sent to the API, a Create tab whose results appear nowhere, duplicated effects, a layer tree with nothing to show (detection removed), and editor state that leaks across routes. None of it feels working because none of it is finished.

## The redesign: "One photo. One bar. Every edit is a branch."

The editor collapses to a single honest surface:
- **Center:** the photo (zoom/pan)
- **Left rail:** branch filmstrip — every edit creates a new photo beside the original
- **Right rail:** one chat bar — the only control surface
- **Top bar:** breadcrumb + Download + Share

Zero dead controls. Every feature earns its place by a live demo before the next is built.

## Step 0 — Strip + core loop (the words-edit)

**Remove from the editor UI:** the entire tools pill (all 8 tools), the "Your regions" tree (delete `ElementTree.tsx`), the marquee/chips/Apply-N annotate flow, text annotations, bulk bar, image switcher, fullscreen, Create/Edit tabs, Reference-image dropdown, version dropdown, Enhance button, undo/redo buttons, composer palette/mention/attach buttons, dead exports and duplicate effects.

**Keep:** zoom/pan canvas (geometry.ts stays), filmstrip, Download, Share, the composer (text + send only).

**One backend addition:** `POST /api/images/:id/edit { prompt }` → whole-photo edit job (reuses the proven `runWholePhotoEdit` pipeline; everything else in the backend stays untouched).

**The core loop:** type any change ("make the wall white") → progress → app navigates to the **branched photo** → filmstrip shows original → branch.

**Fix while in there:** editor store resets on image change; the editor composer calls the direct endpoint (no thread machinery in the editor).

**Verify:** on production — type an edit → branch appears → filmstrip navigates → screenshots.

## Step 1 — Region edit (your recording's core loop)

Draw a rectangle on the photo → small floating "Describe edits" input at the rect → **Apply** → region-scoped edit → branched photo. One instruction at a time (no multi-chip batching yet). Backend reuses the existing instruction + apply pipeline almost as-is.

**Verify:** draw → describe → apply → branch reflects the region change.

## Step 2 — Before/after compare

On any branched photo: a drag slider wiping between the branch and its source. Pure client-side; makes every edit trustworthy.

**Verify:** wipe slider works on a real branch.

## Step 3 — One-tap presets

Chips above the composer: **Enhance · Remove background · Black & white · Restore old photo**. Each = a canned, tested prompt through the same whole-photo edit → branch.

**Verify:** each preset produces a visibly correct branch.

## Step 4 — History & versions

Version dropdown on the viewed branch + undo/redo, now meaningful because branches and edits exist.

## Rules for every step

- **One feature per deploy.** After each: `pnpm check` green → `wrangler deploy` → **browser-verified on production** with screenshots before the next step starts.
- Backend pipelines (jobs, branches, versions, batch edit) stay as-is — only the one new edit route is added in Step 0.
- Dead code removed as encountered; `ElementTree.tsx` deleted in Step 0.
- If a feature can't be made to actually work in its step, it gets removed rather than half-shipped.
